# getConditionsByGameIds

Fetches detailed conditions data for a given list of game IDs. Returns comprehensive condition information including outcomes, odds, and game relationships.

#### Usage

```ts
import { getConditionsByGameIds } from '@azuro-org/toolkit'


const conditions = await getConditionsByGameIds({
  chainId: 137,
  gameIds: ['1006000000000077484167'],
})
```

#### Props

```ts
type GetConditionsByGameIdsParams = {
  chainId: ChainId
  gameIds: string | string[]
  extended?: boolean // opt-in: include new conditions/markets not present in the dictionaries package
}
```

<Callout type="info">
  **When to enable `extended`**

  Optional, defaults to false. When true, the API additionally returns new-generation conditions and outcomes alongside the standard set. Detect a new condition by its first character: `conditionId[0] === '5'`.

  **Titles are returned directly in the response.** Each condition exposes title (the market name), and each outcome exposes its own title — `ConditionDetailedData.title` and `OutcomeData.title`. The toolkit and SDK already handle grouping, sorting, and rendering of new markets out of the box.

  - If your app reads market/outcome metadata only from these hooks’ / utility’s response (no direct use of `@azuro-org/dictionaries`), **enabling the flag is safe** — new markets will appear automatically.
  - If your app reads from `@azuro-org/dictionaries` directly, note that **new markets are not in the dictionaries package** — their titles live only on the API. Use the title fields returned here.

  If you only have a conditionId later (e.g. in a betslip, history, or activity feed) and need its market title, call [getConditionsState](https://gem.azuro.org/hub/apps/toolkit/feed/getConditionsState) — its ConditionStateData now exposes title for the condition and each outcome. The SDK’s [useConditionsState](https://gem.azuro.org/hub/apps/sdk/watch-hooks/useConditionsState) wraps that endpoint.

  **For new bets, titles also are present in the subgraph.**
</Callout>

#### Return Value

```ts
type GetConditionsByGameIdsResponseResult = ConditionDetailedData[]
```

```ts
type ConditionDetailedData = {
  id: string
  conditionId: string
  state: ConditionState
  title: string // market title
  isExpressForbidden: boolean
  isPrematchEnabled: boolean
  isLiveEnabled: boolean
  hidden?: boolean
  margin: string
  outcomes: OutcomeData[]
  category: ConditionCategory
  game: {
    gameId: string
    sport: {
      sportId: string
    }
  }
  /** win-only, condition-level list. NOT the per-outcome source of truth - read `OutcomeData.state` */
  wonOutcomeIds: string[]
  sort: `${number}`
  /** Modern ("5...") conditions only: used for market grouping */
  marketId?: string | null
  marketVarietyId?: string | null
}

type OutcomeData = {
  title: string // outcome title
  outcomeId: string
  odds: string
  sort: `${number}`
  /** Modern ("5...") conditions only: numeric handicap/line value, e.g. "-2.5" / "+2.5" */
  point?: string | null
  hidden: boolean
  state: OutcomeState
}
```

<Callout type="warning">
  **A condition is only ever `Active` or `Stopped`; settlement lives on each outcome.**

  `ConditionState` no longer has `Resolved`, `Canceled` or `Removed` — a condition tells you whether it is
  taking bets, nothing more. Within one condition, outcomes settle independently: one can be `Won`, another
  `Lost`, a third `Canceled` (voided, stake refunded) and a fourth still `Active`.

  Read `OutcomeData.state`, or [`isOutcomeSettled`](/hub/apps/toolkit/utils/isOutcomeSettled), for a
  result. `wonOutcomeIds` is still served, but it only ever describes wins — it cannot tell a loss apart
  from a void or from an outcome that hasn't settled yet.
</Callout>

```ts
enum ConditionState {
  Active = 'Active',
  Stopped = 'Stopped',
}

enum OutcomeState {
  Active = 'Active',
  Canceled = 'Canceled',
  Stopped = 'Stopped',
  Won = 'Won',
  Lost = 'Lost'
}

type ConditionCategory =
  | 'correct_score'
  | 'handicap'
  | 'handicap_3_way'
  | 'odd_even'
  | 'participant_and_total'
  | 'participant_and_yes_no'
  | 'participant_slash_participant'
  | 'players'
  | 'result'
  | 'result_or_neither'
  | 'total'
  | 'total_3_way'
  | 'winner'
  | 'yes_no'
  | string // extensible — new categories may appear; null when unset
  | null
```
